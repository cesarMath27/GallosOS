# Local Root Recovery Access Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an organizer declare a root password hash in `gallos.toml` that `gallos-daemon` applies at every boot/reload, so `su root` works from the `foot` terminal already available in the kiosk session — no SSH, no network component, available in every mode including Contest.

**Architecture:** A new `daemon/src/root_access.py` module wraps `chpasswd -e` / `passwd -l root`. `daemon/src/config.py` gains a `recovery.root_password_hash` field that is **always** re-sourced from the local baked-in `gallos.toml` only — never from a remote-fetched one, even if the active config came from a URL — so the secret can never transit or rest in a possibly-shared remote config file. `daemon/src/main.py` applies it once per `reload_config()` call (boot + every `RELOAD` IPC command); there is no mode-gating logic, since the root password is available in every mode including Contest.

**Tech Stack:** Python 3.10+ stdlib only (`subprocess`, `tomllib`), `chpasswd`/`passwd` from the base `passwd` package (already present, no new `apt` dependency), `pytest` + `unittest.mock`, `ruff`.

**Spec:** `docs/ROOT_ACCESS.md` — read it first. This plan resolves the one question that document left open ("Contest-mode gating") as **Option B: available in every mode, including Contest** (maintainer's explicit choice — see conversation history, not repeated here). Everything else in that document (local-only scope, no SSH, secret-handling risk) still applies and is implemented below.

## Global Constraints

- Python `>= 3.10` (`pyproject.toml` `requires-python`).
- **No SSH, no port 22, no firewall change of any kind.** Out of scope for this plan entirely (deferred to a future Venue Controller phase per `docs/ROOT_ACCESS.md`).
- **Never store or transmit the plaintext root password.** Only a `crypt`-format hash (`$6$...` / `$y$...`) ever appears in `gallos.toml`, generated by the organizer on their own machine (e.g. `openssl passwd -6`).
- **`recovery.root_password_hash` must never be sourced from a remotely-fetched `gallos.toml`.** Always re-read from the local baked-in file only, regardless of where the rest of the active config came from.
- English only in code, comments, and docs (`AGENTS.md` rule 1).
- Every task must leave `./scripts/check.sh` passing (`ruff check .`, `ruff format --check .`, `pytest daemon/tests/ -v`, `shellcheck`, TOML validation) — see `docs/DEVELOPMENT.md`.
- No `sudo`/root-lock behavior for the `contestant` user changes — this plan only touches the separate `root` account.

```python
"""Root Recovery Access module for GallosOS Daemon.

Applies or clears a locally-declared root password hash for `su` recovery
access from within the kiosk session. No SSH/network component — see
docs/ROOT_ACCESS.md for the full design and its explicitly-deferred scope.
"""

import subprocess
import sys


def set_root_password(password_hash: str | None) -> None:
    """Applies the configured root password hash, or re-locks root if unset."""
    if password_hash:
        print("[root_access] Applying configured root password hash for local su recovery.")
        try:
            subprocess.run(
                ["chpasswd", "-e"],
                input=f"root:{password_hash}\n",
                text=True,
                check=True,
            )
        except subprocess.CalledProcessError as e:
            print(f"[root_access] Failed to apply root password hash: {e}", file=sys.stderr)
    else:
        print("[root_access] No root password hash configured; keeping root locked.")
        subprocess.run(["passwd", "-l", "root"], check=False)
```

Add this function right before `load_active_config()` (after `is_config_expired`, currently ending at line 157):

```python
def _load_local_recovery_hash() -> str | None:
    """Loads recovery.root_password_hash from a local baked-in gallos.toml only.

    Deliberately never sourced from a remotely-fetched config: gallos.toml can be
    hosted on a shared Gist/server (see fetch_remote_config above), and a root
    password hash traveling through and resting in that file would defeat the
    point of keeping it secret. See docs/ROOT_ACCESS.md.
    """
    local_data, _ = load_local_config()
    if local_data:
        return local_data.get("recovery", {}).get("root_password_hash")
    return None
```

Then in `load_active_config()`, immediately before the final `print(f"[config] Active configuration source: ...")` line, add:

```python
    # Always re-sourced from local-only, regardless of config_data's own origin above —
    # a fresh dict assignment, never a mutation of a dict that might alias DEFAULT_CONFIG.
    config_data["recovery"] = {"root_password_hash": _load_local_recovery_hash()}
```

**Important:** this must be a plain `config_data["recovery"] = {...}` assignment, not `config_data.setdefault("recovery", {})[...] = ...`. When `config_data` came from `DEFAULT_CONFIG.copy()` (the "no external config found" branch), that's a *shallow* copy — nested dicts are shared references with the module-level `DEFAULT_CONFIG` constant. Using `.setdefault(...)[...]  =` would mutate `DEFAULT_CONFIG["recovery"]` itself, corrupting it for every subsequent call in the process. A plain assignment replaces the key with a brand-new dict and never touches whatever it previously pointed to.

- [x] **Step 3: ⚠️ Flag for real-boot verification — do not claim this works from this step alone**

If the lock file creation fails under the sandbox, `root_access.py`'s `except subprocess.CalledProcessError` (Task 2) catches it safely — root simply stays in its previous (locked, since that's the shipped build-time default) state, which is a safe failure mode, not a security hole.
